# 监理日志 / 监理周报

## 前置

先执行 `it-supervision-core` 第 0 步读取项目档案；`CORE_DIR=<本目录>/../it-supervision-core`。

## 输入

用户通常给的是**非结构化**内容：语音转文字、微信群聊天、照片 + 一句话说明、Excel 片段。你的任务是“整理”，**不是“创作”**：

- 只记录用户给出的事实；不得补充未发生的工作、未出现的人员、未提供的数据。
- 日期、天气（软件项目可写“室内作业/不适用”）、到场人员、工作内容、发现问题、处理情况。
- 缺天气、记录人等基础字段时标【待填】。

## 日志工作流

1. 分配编号：每天一份，`next_doc_no.py --type RZ --title "监理日志 2026-11-26"`。
2. 按 [templates/监理日志.md](templates/监理日志.md) 整理：
   - “工作内容”按 **质量(Q)/进度(S)/投资(C)/合同(H)/信息(I)/协调(X)** 归类，每条前加控制域代码。
   - 监理活动写明方法：旁站/巡视/见证/审核/抽检/会议。
   - 涉及设备写明型号/编号/序列号；涉及软件写明系统/模块/版本。
3. **问题识别**：对每个问题判定严重程度
   - 一般：口头/联系单提醒，在日志中跟踪；
   - 较重（影响质量、进度偏差超过阈值、违反合同/标准）：在“需签发文书”中列出，建议调用 `supervision-notice` 签发监理通知单；
   - 严重（安全事故隐患、重大质量问题、擅自变更）：建议总监签发工程暂停令。
4. **问题跟踪**：读取前一份日志的“遗留问题跟踪”表，逐条更新状态（未整改/整改中/已整改待复查/已关闭）。
5. 输出草稿 → 用户确认 → `validate_doc.py` → `md_to_docx.py`。

## 周报工作流

1. 读取本周（周一至周日）全部 `02-监理日志/*.md`。
2. 按 [templates/监理周报.md](templates/监理周报.md) 汇总：本周工作、进度对比（计划 vs 实际，偏差天数/百分比）、质量情况、到货与付款、问题与整改闭环统计、下周计划、需建设单位协调事项。
3. 统计数字（问题数、关闭数、到货批次）必须能从日志中逐条追溯；不得估算。
4. 编号用 `--type ZB`；签章栏用三方签收样式。

## 措辞示例

| 甲方说要加个报表 | H｜甲方（建设单位）代表口头提出新增统计报表需求，监理提示须走变更程序，请承建单位提交变更申请并评估工期与费用影响。 |
| 进度慢了 | S｜截至今日，“系统联调”计划完成 60%，实际完成约【待填】%，偏差【待填】。 |
