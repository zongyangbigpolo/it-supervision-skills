# 现场照片自动配图

## 能力边界（先跟用户说清楚）

- 照片**必须带可识别的关键信息**：文件名、所在文件夹名或水印中至少有一处含**序列号、设备编号、问题关键词或日期**。像 `服务器_20261120.jpg` 这种文件名只能区分类型和日期，要分到具体设备得靠水印里的序列号。
- 水印识别用**本地 OCR**，照片不上传。150 张大约 1–3 分钟，结果有缓存，二次运行只需几秒。
- 自动匹配是**辅助**：先出《照片匹配报告》，监理人员确认后才生成正式件。低置信度匹配默认**不采用**。
- 你（Agent）**不得**凭照片内容猜测设备归属后写进匹配表，除非是用户要求你看图识别；看图识别的结果写入 `--extra-text` CSV，并在报告中标“人工识别”。

## 前置

1. 先执行 `it-supervision-core` 第 0 步。`CORE_DIR=<本目录>/../it-supervision-core`，`SKILL_DIR=<本目录>`。
2. 依赖：`python-docx`、`Pillow`（必需，用于自动纠正手机照片方向和压缩）；OCR 推荐 `pip install rapidocr onnxruntime`。没有 OCR 时只按文件名、文件夹名和 EXIF 匹配，并提示用户安装。
3. 读 [references/照片位与命名规范.md](references/照片位与命名规范.md)。

## 工作流（用户一句话：“把 D:/现场照片 里的照片贴到第 1 批到货验收单里”）

1. **确定目标文书**，检查其中是否已有 `{{照片:…}}` 照片位：
   - 到货验收单：设备明细表用 `compare_delivery.py --photo-slots` 自动生成“现场照片”列，每台设备一个 `{{照片:序列号}}`；
   - 通知单问题条目：`- **现场照片：** {{照片:序列号&关键词}}`；
   - 监理日志：`{{照片:日期=2026-11-26}}`；
   - 没有照片位时，按用户意图在对应位置插入，插入后给用户看一眼。
2. **匹配**：
   ```bash
   python3 "${SKILL_DIR}/scripts/photo_match.py" "<照片文件夹>" --doc <文书.md> -o 监理资料/照片匹配
   ```
   产出：`照片匹配表.csv`（可用 Excel 编辑）、`照片匹配报告.md`、`ocr缓存.json`。
3. **向用户汇报**报告摘要：已配图/缺照片/待确认/未匹配/一图多位/照片过多，并列出前若干项。请用户：
   - 确认或修改匹配表的“采用”“图注”两列；
   - 对缺照片的设备补拍或手工指定（在 CSV 里新增一行：占位符 + 照片路径 + 采用=是）。
4. **未匹配照片的处理**：先看报告第五节“识别到的文字”。若水印识别失败且数量不多（≤20 张），可在用户同意后由你逐张查看图片，把识别出的关键信息写入 `人工识别.csv`（列：照片文件,文字），再带 `--extra-text 人工识别.csv` 重跑。
5. **渲染**：
   ```bash
   python3 "${CORE_DIR}/scripts/md_to_docx.py" <文书.md> --photos 监理资料/照片匹配/照片匹配表.csv -o 监理资料/正式件/
   ```
   照片会自动纠正方向、压缩到长边 1600 px，表格单元格内按列宽缩放，正文中每行 2 张。没有照片的照片位显示“【待补照片：…】”，并在命令行列出。
6. 正式件交付前，确认命令行没有“待补照片”警告，或用户已同意保留。

## 匹配规则速查

| 写法 | 含义 |
|---|---|
| `{{照片:SN-A0003}}` | 文件名/文件夹/水印中含该编码（忽略大小写和 `-_/.` 分隔符，容忍 O/0、I/1 等 OCR 常见混淆） |
| `{{照片:SN-A0003\|FW-01}}` | 任一命中（“或”）。注意在 Markdown 表格单元格里竖线要写成 `\|` |
| `{{照片:SN-A0003&铭牌}}` | 同时命中（“且”），用于区分同一设备的铭牌照、加电照 |
| `{{照片:日期=2026-11-26}}` | 拍摄日期（水印、文件名、EXIF 任一）为当天 |
| `{{照片:日期=2026-11-26&布线}}` | 当天且含“布线” |

置信度：**高**（精确命中）/ **中**（前后缀粘连、OCR 混淆字符）→ 默认采用；**低**（相似度近似）→ 默认不采用，需人工确认。
