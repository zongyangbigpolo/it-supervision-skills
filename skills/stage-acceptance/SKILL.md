# 阶段验收

## 前置

先执行 `it-supervision-core` 第 0 步；`CORE_DIR=<本目录>/../it-supervision-core`。

## 验收类型与前置条件

先确定验收类型，再按 [references/验收条件与资料清单.md](references/验收条件与资料清单.md) 核对**前置条件**与**应交资料**：

| 类型 | 典型触发 | 关键前置条件 |
|---|---|---|
| 设计阶段验收 | 需求/设计评审完成 | 需求规格、设计文档经评审并确认 |
| 到货与安装验收 | 硬件全部到货安装 | 全部批次到货验收单已签；安装调试记录 |
| 软件部署/系统联调验收 | 功能开发与集成完成 | 系统测试报告；缺陷清零或经确认 |
| 初步验收（初验） | 合同内容全部实施完成 | 自检报告、测试报告、等保测评报告（如合同要求初验前完成）、文档齐全 |
| 试运行验收 | 试运行期满 | 试运行报告、问题处理记录 |
| 终验（竣工验收） | 试运行合格、遗留问题关闭 | 全部遗留问题关闭、竣工资料移交、等保测评通过 |

前置条件不满足时：**不要生成“同意通过”的结论**，改为输出《验收条件不具备说明》或建议签发监理通知单。

## 工作流

1. 收集：验收申请（承建单位）、合同/里程碑定义、交付物清单、测试/测评报告、前期问题台账。
2. 分配编号：`next_doc_no.py --type YS --title "初步验收监理意见"`。
3. 按 [templates/阶段验收监理意见.md](templates/阶段验收监理意见.md) 起草：
   - **验收范围**：逐项列出本阶段合同内容（取自合同/里程碑定义），并标注完成状态。
   - **检查情况**：按 质量/进度/投资/合同/信息 五方面写；数据须有来源（测试报告编号、到货单编号、问题台账）。
   - **资料审查**：用资料清单逐项勾选“齐全/不全/不适用”。
   - **遗留问题清单**：每条有责任单位、整改期限、验证方式；严重程度分 A（影响使用/安全，须验收前解决）/B（不影响主要功能，限期解决）/C（建议改进）。
   - **验收结论**三选一：同意通过 / 有条件通过（存在 B/C 类遗留问题，限期整改）/ 不同意通过（存在 A 类问题或前置条件不足）。**存在 A 类问题时不得写“同意通过”或“有条件通过”**。
4. 结论由用户（监理工程师）最终确认；你只给出建议结论与理由。
5. 校验 & 渲染（三方签章栏，可加验收专家组签字页）。

## 输出

- 《阶段验收监理意见》（YS）
- 附件：遗留问题清单（可单独渲染）、验收资料清单
- 同步更新 `监理资料/03-监理通知单/问题闭环台账.md`（遗留问题进台账跟踪）
