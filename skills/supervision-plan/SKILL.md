# 监理规划 / 监理实施细则

## 前置

1. 先执行 `it-supervision-core` 的“第 0 步”，读取或建立 `监理资料/项目档案.yaml`。
2. 设 `CORE_DIR=<本目录>/../it-supervision-core`（脚本与规范均在其中）。
3. 读取 `${CORE_DIR}/references/三控两管一协调框架.md`、`签章栏规范.md`、`文书规范与编号.md`。

## 需收集的输入（缺失则标【待填】）

| 必需 | 输入 | 来源建议 |
|---|---|---|
| ✔ | 项目概况：建设内容、规模、地点、投资、工期 | 合同/招标文件/可研批复 |
| ✔ | 建设内容清单：软件子系统、硬件设备、机房/布线、安全建设 | 合同附件、投标报价清单 |
| ✔ | 监理范围与监理服务期 | 监理合同 |
| ✔ | 监理机构人员：总监、监理工程师、监理员及分工 | 监理单位 |
| | 里程碑计划 | 承建单位进度计划 |
| | 等保等级、是否需密评 | 建设单位/定级报告 |
| | 建设单位特殊要求（例会频次、报表格式、信创要求） | 建设单位 |

用户若上传合同、招标文件、投标文件，优先从中**摘录**而不是改写事实；摘录处注明出处（文件名+章节/页码）。

## 工作流

1. **确定文书**：监理规划（GH，项目级，一份）还是监理实施细则（XZ，按专业/子系统，可多份，如“硬件集成监理实施细则”“软件开发监理实施细则”“等保建设监理实施细则”）。
2. **分配编号**：`python3 "${CORE_DIR}/scripts/next_doc_no.py" --type GH --title "监理规划"`。
3. **起草**：复制 [templates/监理规划.md](templates/监理规划.md)（或 [templates/监理实施细则.md](templates/监理实施细则.md)），逐章填写：
   - 第 4 章“监理工作内容”必须**按项目实际建设内容裁剪**：无机房工程则删掉机房条目；有等保要求则加入等保节点；有信创要求则加入信创适配检查。
   - “质量控制点”表从 [references/软硬件项目质量控制点.md](references/软硬件项目质量控制点.md) 选取与本项目相关的条目，并标明 **H（停止点，监理签认前不得进入下道工序）/W（见证点）/R（文件审查点）**。
   - 进度控制写明进度检查频次、偏差阈值（如关键路径滞后 ≥ 7 日历天或里程碑滞后 ≥ 5% 发监理通知单）。
   - 投资控制写明付款节点与对应的监理签认条件（例如“到货款：到货验收单三方签章 + 发票”）。
4. **自检**：对照下方检查清单；运行 `python3 "${CORE_DIR}/scripts/validate_doc.py" <草稿>`。
5. **交付草稿**：输出 Markdown 草稿与“待补充信息清单”，请用户确认。
6. **出正式件**：用户确认后 `validate_doc.py --final` 通过，再 `md_to_docx.py` 渲染到 `监理资料/正式件/`。

## 检查清单

- [ ] 工程概况与合同一致（金额、工期、建设内容）
- [ ] 监理范围、监理服务期与监理合同一致
- [ ] 三控两管一协调六章俱全，且每章有“目标—方法—措施—输出文书”
- [ ] 质量控制点表已按项目裁剪，H/W/R 标识完整
- [ ] 监理工作程序含：开工审查、到货验收、阶段验收、变更、付款审核、问题整改闭环
- [ ] 监理文书清单与编号规则已列出
- [ ] 编审批签章栏存在（`<!-- signature:compile-approve -->`）
- [ ] 无编造的人员姓名、证书编号、标准条款号
