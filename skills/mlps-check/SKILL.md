# 等保测评监理检查

## 定位

监理**不替代测评机构**做测评，而是对等保工作的**过程与结果**进行监督：节点是否按时、资料是否齐全、测评范围是否与建设范围一致、问题是否整改闭环、结论是否满足合同要求。措辞中避免“监理测评认为……”，应写“经监理核查……”。

## 前置

先执行 `it-supervision-core` 第 0 步（项目档案中的 `等保` 段落）；`CORE_DIR=<本目录>/../it-supervision-core`。阅读 [references/等保监理检查要点.md](references/等保监理检查要点.md)。

## 检查节点（可分次出表，每次一份 DB 编号）

| 节点 | 检查内容 | 主要证据 |
|---|---|---|
| ① 定级备案 | 定级对象划分、定级报告、专家评审、主管部门意见（如有）、公安机关备案 | 定级报告、专家评审意见、备案表、备案证明 |
| ② 安全设计 | 安全设计方案是否覆盖对应等级的技术与管理要求 | 安全设计方案、评审意见 |
| ③ 建设整改 | 差距分析结果、整改方案、整改实施情况（技术 + 管理） | 差距分析报告、整改记录、配置截图、制度文件 |
| ④ 测评过程 | 测评机构资质、测评方案、测评范围与系统边界一致、现场测评监理见证 | 机构资质证明、测评方案、见证记录 |
| ⑤ 测评结果 | 测评结论与得分、高/中风险项、是否满足合同要求 | 等级测评报告 |
| ⑥ 整改闭环 | 测评发现问题的整改、复测 | 整改跟踪表、复测记录 |

## 工作流

1. 确认等级（第二级/第三级/第四级）与检查节点；未定级时，节点①是首要事项。
2. 分配编号：`next_doc_no.py --type DB --title "等保测评监理检查表（节点③）"`。
3. 按 [templates/等保测评监理检查表.md](templates/等保测评监理检查表.md) 填写；技术/管理检查项按等级从 `references/等保监理检查要点.md` 挑选。
4. 每项结果只能填 **符合/基本符合/不符合/不适用/未提供资料**，并写证据（文件名、截图编号、见证时间）。**没有证据就填“未提供资料”**，不能推测为符合。
5. 对“不符合”项：生成 [templates/等保整改跟踪表.md](templates/等保整改跟踪表.md) 条目（编号 `--type ZG`，整个项目滚动更新同一份即可），并建议调用 `supervision-notice` 签发监理通知单。
6. 测评报告审核：从报告中摘录结论（优/良/中/差）、综合得分、高/中/低风险项数量；与合同要求对比给出监理意见。数字必须来自报告原文，用户未提供则标【待填】。
7. 校验 & 渲染；签章栏为三方 + 测评机构（节点④⑤）。

## 红线（出现即在结论中明确提示）

- 第二级及以上系统未完成公安机关备案即上线运行；
- 测评范围小于实际建设/上线范围（漏测资产）；
- 测评报告存在未处置的**高风险**项；
- 测评机构资质无法核实；
- 默认口令、弱口令、未修复的已知高危漏洞、重要数据未备份等在现场核查中被发现。
