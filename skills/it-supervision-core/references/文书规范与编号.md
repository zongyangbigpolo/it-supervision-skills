# 文书规范与编号

## 一、编号规则

格式：`JL-<项目简称>-<类型码>-<年份>-<三位流水号>`，例：`JL-ZHZW-TZ-2026-003`。

| 类型码 | 文书 | 所属 skill |
|---|---|---|
| GH | 监理规划 | supervision-plan |
| XZ | 监理实施细则 | supervision-plan |
| RZ | 监理日志 | supervision-log |
| ZB | 监理周报 | supervision-log |
| YB | 监理月报 | supervision-log |
| TZ | 监理通知单 | supervision-notice |
| HF | 监理通知回复单（承建单位填写，监理复核） | supervision-notice |
| ZT | 工程暂停令 | supervision-notice |
| FG | 复工令 | supervision-notice |
| LX | 监理工作联系单 | supervision-notice |
| YS | 阶段验收监理意见/验收报告 | stage-acceptance |
| DB | 等保测评监理检查表 | mlps-check |
| ZG | 等保整改跟踪表 | mlps-check |
| DH | 硬件设备到货验收单 | hardware-arrival-check |
| HY | 会议纪要 | 通用 |

- 项目简称取自 `项目档案.yaml` 的 `项目简称`（建议 2–6 位大写拼音首字母）。
- 流水号按“项目 + 类型 + 年份”独立递增，由 `scripts/next_doc_no.py` 维护 `监理资料/编号台账.csv`，**不得手工跳号或重号**。
- 回复单编号与被回复通知单关联：在“关联文书”字段写原通知单编号。
- 若建设单位或地方监管部门有既定编号规则，以其为准，在项目档案 `编号前缀` 中覆盖 `JL`。

## 二、版式规范（DOCX 渲染脚本已内置）

- 纸张 A4 纵向；上 2.54 cm、下 2.54 cm、左 2.8 cm、右 2.6 cm（左侧留装订边）。
- 标题：宋体（或方正小标宋）二号加粗居中；表头信息用表格。
- 正文：仿宋_GB2312 / 仿宋 四号或小四；表格内小五至五号；行距 1.5 倍。
- 页眉：项目名称 + 监理单位；页脚：“第 X 页 共 Y 页”。
- 文书一式份数写在签章栏下方，例：“本单一式肆份，建设单位、承建单位各壹份，监理单位贰份。”

## 三、措辞规范

| 不要写 | 应写 |
|---|---|
| 乙方、施工方、厂家 | 承建单位（首次出现可注“乙方”）；供货单位 |
| 甲方、业主 | 建设单位（首次出现可注“甲方”） |
| 大概、差不多、基本没问题 | 经核查，符合/不符合……要求 |
| 赶紧改 | 请于 2026年12月1日前完成整改，并以《监理通知回复单》书面回复 |
| 服务器坏了 | 编号为 xx 的服务器（SN：xxx）加电自检报内存故障告警 |
| 我们认为 | 监理意见： / 监理机构认为： |

- 问题描述“四要素”：**时间、地点/对象、事实、依据**。
- 要求“三要素”：**整改内容、完成期限、回复方式**。
- 结论用词：
  - 验收类：“同意通过 / 有条件通过（遗留问题限期整改） / 不同意通过”。
  - 检查类：“符合 / 基本符合 / 不符合 / 不适用”。

## 四、日期、数量、金额

- 日期：`2026年11月26日`；时间：`14:30`。
- 数量带单位：`48 台`、`1,200 m`、`3 套`。
- 金额：`人民币壹拾贰万叁仟肆佰元整（¥123,400.00）`。调用脚本中的大写转换函数，避免手工出错。
