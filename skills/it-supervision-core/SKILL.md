# 信息技术服务监理 · 总控

本 skill 是整套信息监理 skill 的“底座”。其他子 skill 都依赖这里的**项目档案、编号规则、签章栏、输出目录与 DOCX 渲染脚本**。任何监理文书任务开始时，先按本文件完成“第 0 步”，再进入对应子 skill。

## 子 skill 路由

| 用户意图（关键词） | 使用的 skill | 主要产出 |
|---|---|---|
| 监理规划、监理大纲、监理实施细则、项目开工准备 | `supervision-plan` | 《监理规划》《监理实施细则》 |
| 监理日志、监理日记、今天现场情况、巡视记录、周报/月报素材 | `supervision-log` | 《监理日志》（日）/《监理周报》 |
| 监理通知单、整改通知、停工令、暂停令、复工令、工作联系单、问题闭环 | `supervision-notice` | 《监理通知单》《监理通知回复单》《工程暂停令》《监理工作联系单》 |
| 阶段验收、里程碑验收、初验、终验、试运行、上线验收、软件测试验收 | `stage-acceptance` | 《阶段验收监理意见》《验收报告》《遗留问题清单》 |

用户只说“帮我出一份监理资料”而未说明类型时，用 `ask_user`（或等价的提问方式）让用户在上表中选择，不要自行猜测。

## 第 0 步：建立/读取项目档案（必做）

1. 在用户的工作目录下查找 `监理资料/项目档案.yaml`。
2. 若不存在，以 [templates/项目档案.yaml](templates/项目档案.yaml) 为模板向用户**一次性**收集关键信息（项目名称、建设单位、承建单位、监理单位、合同编号与金额、工期、总监/监理工程师、项目简称），写入 `监理资料/项目档案.yaml`。未知项保留 `【待填】`，不得编造。
3. 若已存在，直接读取并复用，不要重复询问；用户提供的新信息要回写到档案中。
4. 所有子 skill 生成的文书，表头信息（项目名称、各方单位、合同编号、编号）一律取自项目档案，保证全套资料口径一致。

## 核心原则

- **事实优先，绝不编造**：日期、数量、金额、序列号、测评分数、人员姓名等事实性内容，只能来自用户输入、用户提供的附件或项目档案；缺失时写 `【待填】` 并在输出末尾列出“待补充信息清单”。
- **监理立场中立**：监理代表建设单位进行监督，但措辞客观、依据充分。每条问题须写明“依据”（合同条款/标准条款/设计文件/会议纪要），每条要求须写明“整改期限”和“回复方式”。
- **三控两管一协调贯穿全部文书**：每份文书都要能映射到 [references/三控两管一协调框架.md](references/三控两管一协调框架.md) 中的一个或多个控制域，并在文书的“控制域”字段注明。
- **可签可盖**：每份正式文书末尾必须带签章栏，签章栏格式统一取自 [references/签章栏规范.md](references/签章栏规范.md)。不同文书需要签章的单位不同，按该规范的矩阵选取。
- **先草稿后正式**：先输出 Markdown 草稿给用户确认；用户确认后再调用脚本渲染为 DOCX 正式件。正式件不得残留 `【待填】`（脚本会校验）。
- **中文公文风格**：使用简体中文、书面语、阿拉伯数字表达日期与数量（例：2026年11月26日），金额用“人民币（大写）+ 小写”双写；不使用口语、网络用语、emoji。
- **术语统一**：建设单位（甲方）、承建单位（乙方）、监理单位、总监理工程师（总监）、监理工程师、监理员；详见 [references/文书规范与编号.md](references/文书规范与编号.md)。

## 输出目录

统一写入用户工作目录下的 `监理资料/`：

```
监理资料/
├── 项目档案.yaml
├── 01-监理规划/
├── 02-监理日志/
├── 03-监理通知单/
├── 04-阶段验收/
├── 05-等保测评检查/
├── 06-到货验收/
├── 照片匹配/        # 照片匹配表.csv、照片匹配报告.md、OCR 缓存
└── 正式件/          # 渲染后的 DOCX，供打印签章
```

文件命名：`<文书编号>_<文书名称>_<YYYYMMDD>.md`，例如 `JL-ZHZW-TZ-2026-003_监理通知单_20261126.md`。

## 脚本

`${CORE_DIR}` 指本 SKILL.md 所在目录。需 Python 3.9+；DOCX 渲染需 `python-docx`（`pip install python-docx`）。

```bash
# 1) 分配下一个文书编号（自动读取/更新 监理资料/编号台账.csv）
python3 "${CORE_DIR}/scripts/next_doc_no.py" --type TZ          # TZ=通知单，见编号规则

# 2) 校验草稿：检查待填项、签章栏、必备章节
python3 "${CORE_DIR}/scripts/validate_doc.py" 监理资料/03-监理通知单/xxx.md

# 3) 渲染为可打印签章的 DOCX（A4、宋体/仿宋、页眉页脚、表格边框）
python3 "${CORE_DIR}/scripts/md_to_docx.py" 监理资料/03-监理通知单/xxx.md -o 监理资料/正式件/

# 4) 带现场照片渲染：文书中写 {{照片:序列号}} 照片位，匹配表由 site-photos skill 生成
python3 "${CORE_DIR}/scripts/md_to_docx.py" xxx.md --photos 监理资料/照片匹配/照片匹配表.csv -o 监理资料/正式件/
```

无法运行 Python 时，直接交付 Markdown，并提示用户用 WPS/Word 打开或用 pandoc 转换。
